# One Item shape for everything Commander tracks

Emails, calendar events, Linear issues, GitHub PRs and review requests, Todos and Daily Note Blocks are all stored as **Items** sharing one core (kind, Source and Account, title, People, Project with how it was filed, timestamps, status), plus kind-specific detail. A Todo is its own Item that can be *backed by* another Item, and Items connect through typed **Links**. We chose this over a separate model per Source because the Dashboard's ranked feed, search, the Project filter, Links, the activity log and Ares all operate across every kind of Item. With separate models, each of those features would be rebuilt once per Source. The cost is a more abstract core table and per-kind detail joins.

**Amendment (#204): a removed Account's tombstones are bare.** Removing an Account deletes its Items as tombstones like any other, so the User's Notes and Todos keep their Links, shown as gone; but it also takes their content out for good (decision #30): each tombstone keeps only its kind, Source, Account and times, titled "Removed with its Account", and the activity log keeps its entries without the states and reasons that copied the content. Its external id becomes `removed:<id>`, so connecting the Account again syncs fresh Items, and undo refuses to bring a bare tombstone back. Everything made from the Items (the word and meaning indexes, memories learned only from them, Ares's answers resting only on them, People handles nothing else names) goes with them, and the database file is rewritten so no deleted page still holds it. Snapshots keep it until they age out; Wipe all Commander data removes everything at once.
