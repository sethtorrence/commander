# Daily Notes are Items, and a Link can point at a Project

A **Daily Note** is itself an Item (kind `daily-note`, one per calendar day), with its Blocks as Items under it. A `[[day]]` link from a Block is then an ordinary **refers to** Link to an Item, and "Mentioned in" on a day's sheet is the same backlinks query every other Item uses. Linking to a day with no Daily Note yet creates the empty Daily Note Item, so every Link has a real target. This extends ADR 0001, which named Blocks but not the Daily Note.

A **Project** is not an Item: Items belong to Projects, and a Project that was also an Item would need a Project of its own. But `[[Project]]` links and the Project page's "Mentioned in" need a Link to reach a Project. So a Link's target is either an Item or a Project, stored in the one Link table with a target-type column, and answered by the one backlinks query. Only **refers to** Links may target a Project; every other Link type still joins two Items.

We chose this over a separate "mentions" table for Projects, which would split backlinks into two queries and two code paths, and over making Projects Items, which would tangle the Project filter and filing with the thing being filed into. The cost is a Link target that is no longer always an Item, which every Link consumer has to handle.

**Amendment (#239): a Block's line has a style, kept beside its text.** Daily Notes write like Markdown rather than as an all-bullets outliner, so each Block now has a **style**: a plain line (the default), a heading (levels 1 to 3), a bullet, a numbered item, a checkbox Todo or a quote. The style is a field of the Block's detail, not a mark kept in its text: the shorthand typed at the start of a line (`- `, `1. `, `## `, `[ ] `) sets it and goes, and Backspace at the line's start takes it off. So a Block's text, title, Links, Project and Todo never depend on how it looks, and everything that reads Blocks (search, Links, Learn facts, Suggest Todos, filing, the Ares button) reads them as before; only the Notes Section and the Markdown copy draw the style. Only bullets and numbered items nest as the User writes, so a Block's parent is again what it is filed under: a nested list item inherits its parent's Project, and a meeting's notes stay under its Meeting chip, drawn as the meeting's quote. A migration gave existing notes their styles (the template's sections subheadings, meetings and the lines under them quotes, Blocks made into Todos checkboxes, the rest plain lines) without changing any text, Link, Project or Todo. We chose a field over keeping the marks in the text (as headings were before) because the Meetings section is found by its text, Todo titles follow it, and every other reader would have had to strip the marks.
