# People match on email addresses only, and the User's arrangements stand

Every Source names people its own way: a Linear user id, a GitHub login, a Microsoft user id, an email address. Commander shows them as one **Person** per human (#117, decision #28), so "Priya" means the same in the Linear Section, a pull request and a Chat, and Ares, Memory and the People view can talk about her work across Sources.

Matching is **deterministic and runs on email addresses only**. A Source names a handle together with an address (a Linear user's email, a GitHub login's public or commit email, a Teams member's address), and the handle joins the Person who has that address, compared case-insensitively. Two People who turn out to share an address become one, logged as `match` in the People log. A handle with no known address is a Person of its own until an address links it. **Names never join anyone**, however alike: two Sam Riveras stay two People until an address, or the User, says otherwise. Display-name likeness may later become a Suggestion, never a merge.

The User corrects the matching: **Merge** two People, **Split** handles out of one, **Rename** anyone. Each is an entry in the People log, which undoes it (People are not Items, so this is kept apart from the Activity log, as the Project log is). Matching must never undo these. So a merge or split **pins** the handles it places: matching never moves a pinned handle, and when an address links two People who both hold pinned handles, they stay apart. Matching only ever adds handles and joins People; it never separates them, so it cannot undo a merge. The User's name for a Person wins over every Source's.

We chose this over fuzzy matching (names, usernames that look alike) because a wrong automatic merge is worse than a missed one. It puts one human's work under another's name everywhere, including in what Ares says. A missed match costs one Merge in Settings → People. The cost is that people a Source gives no address for (a GitHub user with a private email, a Teams guest) stay apart until the User merges them.
